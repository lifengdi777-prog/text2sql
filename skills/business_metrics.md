# 业务指标定义

# ⚠️ 优先级规则(写 Spec 前**必须**先判断这个)

写 ComputeSpec 时,先看用户问的指标(或别名)在当前数据集 schema 里**怎么呈现**:

| 情况 | 怎么办 |
|---|---|
| ✅ **schema 里已经有跟指标同名的列**(例:数据集本来就有 `不良率` / `合格率` 这一列) | **直接用该列**做 filter / order / mean。**忽略下面的公式**,公式是给"原始字段在,衍生指标不在"的情况用的 |
| ⚠️ **schema 里没有指标列,但有依赖的原始列**(例:`defect_quantity` + `actual_quantity` 在,但没有 `不良率` 列) | 用下面的公式,**aggregations 里分别 SUM 分子和分母**(输出两个数,前端再相除) |
| ❌ **两者都没有** | 直接告诉用户"数据里没有 X",**不要硬凑** |

**关键例子**:
- 用户问"不良率最高的工厂",schema 显示 `不良率` 是 numeric 列 → `groupby=工厂, max(不良率)`,**不要用公式**
- 用户问"不良率超过 5% 的工厂",schema 有 `不良率` 列 → `filter 不良率 gt 5, groupby=工厂`,**不要用公式**
- 用户问"不良率",schema 只有 `defect_quantity` 和 `actual_quantity` → 才用公式,分别 SUM
- 用户问"产量达成率",schema 既没 `产量达成率` 列也没 `planned_quantity` → 报错,告诉用户缺数据

# 指标公式参考(只在"无现成指标列、有原始列"时用)

---

## 实际产量
- **别名**:产量 / 总产量 / 实际产出 / 完成产量 / 生产数量 / 产出数量
- **公式**:`SUM(actual_quantity)`
- **单位**:件
- **聚合性**:可加(可直接 SUM)
- **依赖列**:actual_quantity

## 计划产量
- **别名**:目标产量 / 计划数量 / 目标数量 / 生产计划 / 计划总量
- **公式**:`SUM(planned_quantity)`
- **单位**:件
- **聚合性**:可加
- **依赖列**:planned_quantity

## 产量达成率
- **别名**:达成率 / 计划达成率 / 完成率 / 产量完成率 / 生产达成率
- **公式**:`SUM(actual_quantity) / SUM(planned_quantity)`
- **单位**:%(0~1 的小数,前端按需 ×100 显示)
- **聚合性**:**比率指标 —— 不能在已聚合结果上再 SUM**,必须在原始数据上算
- **依赖列**:actual_quantity, planned_quantity

## 合格率
- **别名**:良品率 / 质量合格率 / 通过率 / 合格比例 / 良率
- **公式**:`SUM(qualified_quantity) / SUM(actual_quantity)`
- **单位**:%
- **聚合性**:比率(不可再聚合)
- **依赖列**:qualified_quantity, actual_quantity

## 不良率
- **别名**:次品率 / 缺陷率 / 不合格率 / 报废率 / 不良比例
- **公式**:`SUM(defect_quantity) / SUM(actual_quantity)`
- **单位**:%
- **聚合性**:比率(不可再聚合)
- **依赖列**:defect_quantity, actual_quantity

## 停机时长
- **别名**:总停机时长 / 停机时间 / 停机分钟 / 设备停机时长 / 宕机时间
- **公式**:`SUM(downtime_minutes)`
- **单位**:分钟
- **聚合性**:可加
- **依赖列**:downtime_minutes

## 生产效率
- **别名**:效率 / 单位工时产量 / 生产效能 / 产线效率 / 设备效率
- **公式**:`SUM(actual_quantity) / SUM(production_hours)`
- **单位**:件/小时
- **聚合性**:比率(不可再聚合)
- **依赖列**:actual_quantity, production_hours

---

# 电商 / 订单类指标(适用于含 金额 / 数量 / 订单号 / 客户ID 的订单数据集)

> 同样遵循上面的优先级规则:schema 里有同名列就直接用;下面的公式只在"指标列不在、原始列在"时用。

## 销售额
- **别名**:GMV / 成交额 / 营业额 / 营收 / 销售总额 / 总成交金额
- **公式**:`SUM(金额)`
- **单位**:元
- **聚合性**:可加(可直接 SUM)
- **依赖列**:金额

## 订单数
- **别名**:订单量 / 单量 / 成交笔数 / 下单数 / 订单笔数
- **公式**:`nunique(订单号)`(一单一行时等价于 `count(*)`)
- **单位**:笔
- **聚合性**:去重计数(单聚合即可)
- **依赖列**:订单号

## 客户数
- **别名**:购买客户数 / 下单客户数 / 买家数 / 用户数 / 成交用户数
- **公式**:`nunique(客户ID)`
- **单位**:人
- **聚合性**:去重计数(不能在已聚合结果上再相加)
- **依赖列**:客户ID

## 客单价
- **别名**:AOV / 平均订单金额 / 单均 / 平均客单 / 单均价
- **公式**:`SUM(金额) / nunique(订单号)`
- **单位**:元/单
- **聚合性**:比率(不可再聚合)—— aggregations 里**同时**输出 `SUM(金额)` 与 `nunique(订单号)`,前端相除
- **依赖列**:金额, 订单号

## 件单价(平均售价 ASP)
- **别名**:平均成交价 / 单件均价 / 平均售价 / 件均价
- **公式**:`SUM(金额) / SUM(数量)`
- **单位**:元/件
- **聚合性**:比率(不可再聚合)—— ⚠️ **不是 `mean(单价)`!** 必须金额之和 ÷ 数量之和
- **依赖列**:金额, 数量

## 人均消费(ARPU)
- **别名**:客均消费 / 客均贡献 / 人均贡献 / 人均订单金额
- **公式**:`SUM(金额) / nunique(客户ID)`
- **单位**:元/人
- **聚合性**:比率(不可再聚合)—— **同时**输出 `SUM(金额)` 与 `nunique(客户ID)`,前端相除
- **依赖列**:金额, 客户ID

# 使用约束(给 LLM 的硬规则)

1. **比率类指标**(达成率/合格率/不良率/生产效率/客单价/件单价/人均消费):
   - 写 Spec 时,**分子分母分别聚合(SUM 或 nunique),再相除**;**不要**对原始记录的"率/均价"字段直接 SUM 或 mean(会算错)
2. **条件占比类指标**(退款率 / 会员订单占比 / 各状态占比):
   - 分子是"满足某条件的计数",分母是"全部计数";**一个 Spec 的 filter 全局生效,无法在同一个 Spec 里同时拿到分子和分母**
   - 正确做法:**不要加 filter**,改成 `groupby 该维度(如 订单状态 / 是否会员)+ count`,输出各组计数(分布),由前端/解读再算占比
3. **暂不支持的指标**:
   - **复购率**(需先按客户聚合下单次数、再对结果做阈值计数 —— 两层聚合,Spec 单层结构表达不了)
   - **需要行级派生列再聚合**的指标(如只有 `销量` 和 `单价`、没有 `金额` 列时的"销售额 = Σ(销量×单价)")—— Spec 不支持行级计算列
   - 命中这类 → 直接告诉用户"当前不支持这样计算"
4. **依赖列在数据集里不存在**:
   - 不要硬凑,**直接告诉用户**"数据集里没有这些列,无法计算"
5. **别名识别**:
   - 用户问题里出现任一别名 → 当作该指标处理
   - 多个指标命中 → 同时输出多个聚合
6. **新加指标**:
   - 只能由开发者编辑本文件添加,不要自创
